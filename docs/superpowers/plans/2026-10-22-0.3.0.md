# 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.3.0. Every time charpente stores or compares means the same thing after a
restart, a failover or a wall-clock step. Workloads draw their inputs, and failures shrink.
`charpente test --sim` reads cold. GUIDE and examples ship inside the crates. The two
compatibility principles are written down.

**Architecture:**
- **Time.** `Clock` gains a wall reading of a new storable type, `WallTime` (Unix-epoch
  nanoseconds). `Instant` stays monotonic, process-local and unstorable. The kernel reads both
  each step, holds the wall reading monotonic within `CLOCK_TOLERANCE`, stops by name beyond
  it, and checks a floor recovered from stored times at open and promote.
- **The sim.** It models the wall reading as virtual time + a fixed Unix base + a per-host
  offset, with three new fault axes sampled only on the app harness path.
- **Inputs.** Workloads draw through `sim.input()` from their own keyed stream. The harness
  records each run's choices, shrinks the first failure per check by replaying smaller choice
  sequences with fault axes turned off, and renders a cargo-test-shaped report and JSON.

**Tech Stack:** Rust 1.99 (pinned), the workspace crates, the edge harness (real binaries over
TCP), cargo-mutants 27.1.0 (evidence only), and the launch-run tools
(`docs/experiments/2026-10-launch-run/tools/`).

**Spec:** `docs/superpowers/specs/2026-10-22-0.3.0-design.md` (e0c8d8c5). Executors read it,
and CLAUDE.md, before their task. The spec's §2 principles govern every task: APIs change in
place, and nothing is kept for compatibility.

**Workspace:** `SDD=/Users/noahmitchem/Documents/GitHub/charpente/.superpowers/sdd/2026-10-22-0.3.0`

## Global Constraints

- **Hard rule 1.** `SystemTime` appears only in `crates/charpente/src/prod.rs` and in test or
  edge code that already allows the deny-list. Nothing in `charpente-sim`'s harness reads a
  clock; the shrink budget is a replay count.
- **Determinism.** Every new random behaviour draws from its own `keyed_stream(seed, "<name>")`
  (`charpente-sim/src/lib.rs:520`). `run_universe` (lib.rs:2464, the frozen swarm contract)
  is not edited. The app harness gets its own entry point. A task that moves a recorded batch
  or a pinned seed must be one of the named steps in Task 0's table, and it records the before
  and after. Any other movement is a bug.
- **Exit codes:** 0 green (all-untested included); 1 any failure or unmet `require`; 2 usage,
  build, infrastructure, or no check matched.
- **Copy is binding.** Every product-surface string in this plan is exact and pinned by a test
  (hard rule 5). Where the plan gives no string, the spec's §5 D shape applies.
- **Ordering in output:** checks in registry order; reasons by count descending, then reason
  text ascending (byte order); output byte-identical for any `--jobs`.
- **Hard rule 6:** the docs a task's code changes (GUIDE, DESIGN, README, CHANGELOG's
  `## 0.3.0 (unreleased)` section) land in that same task.
- **Commits:** on `main`, named paths only, no trailers (CLAUDE.md). Immediately before each
  commit, run `git log --oneline -1` and `git status --short`. Stop and report if HEAD moved
  or unrelated files are dirty: another session may share this tree.
- **Verification (implementers):** per-package suites only. Run
  `cargo test -p <pkg> --no-fail-fast 2>&1 | tee $SDD/logs/<task>-<pkg>.log`, take the exit
  from `${pipestatus[1]}` (this shell is zsh), and count `grep -c '^test result: ok'`. Never
  run `cargo test --workspace`: it exceeds the tool ceiling, and the controller runs it in
  `~/Documents/GitHub/charpente-gate`. Bound long runs with
  `perl -e 'alarm N; exec @ARGV' --` (there is no `timeout` on this machine). Run verification
  in the foreground, never backgrounded.
- **fmt and clippy** run before every commit:
  `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings`.
- **Network:** nothing beyond cargo's own fetches and `docker pull`. Never put an email address
  in a request.
- **New workspace crates** (`clock-fixture`, `merge-fixture`) are added to CLAUDE.md's
  workspace map and its test-file list in the same commit. `guide-examples`'
  `doc_inventory` gate enforces this.

## Review Focus

1. **A cron interval or session TTL changed between deploys.** The recovered wall floor must
   not rise above a time the directory actually saw, or a healthy node refuses to open. Test
   in Task 5.
2. **A follower whose clock is behind the primary's, but within `CLOCK_TOLERANCE`.** It must
   promote, never refuse. Test in Task 5.
3. **A malformed or truncated `--inputs` value, or `--inputs`/`--faults-off` without
   `--seed`.** Exit 2 with a message naming the flag, never a panic and never a silent default
   run. Test in Task 12.
4. **A workload that draws a different number of inputs depending on which faults fired**
   (draws inside a retry loop). Shrinking stays deterministic, and the printed repro replays
   the printed failure exactly. Test in Task 12.
5. **A shrink that slips to a different failure message.** The block's headline is the shrunk
   run's own message, the original message is still printed, and the repro replays the shrunk
   one. Test in Task 12.

```rust
// charpente_core::io
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct WallTime { nanos: u64 }          // nanoseconds since 1970-01-01T00:00:00Z
impl WallTime {
    pub const UNIX_EPOCH: WallTime;
    pub fn from_nanos(nanos: u64) -> WallTime;
    pub fn as_nanos(self) -> u64;
    pub fn saturating_sub(self, d: Duration) -> WallTime;
    pub fn saturating_duration_since(self, earlier: WallTime) -> Duration; // 0 if earlier is later
}
impl std::ops::Add<Duration> for WallTime;  // panics on u64 overflow, naming it
impl std::fmt::Display for WallTime;        // RFC 3339 UTC, millisecond precision: 2026-10-22T03:04:05.123Z
pub const CLOCK_TOLERANCE: Duration = Duration::from_secs(60);
pub trait Clock { fn now(&self) -> Instant; fn wall(&self) -> WallTime; fn sleep(&self, d: Duration); }
// charpente_sim
pub const SIM_WALL_BASE_NANOS: u64 = 1_767_225_600_000_000_000; // 2026-01-01T00:00:00Z
```
- `WallTime` gets the table codec, so it can be a `#[table]` field. It encodes as its `u64`.
  `Instant` must never get one.

  the problem, if the system clock is before 1970. `ProdClock` derives `Clone`; a clone shares
  the origin.
- `SimClock::wall` returns `virtual now + SIM_WALL_BASE_NANOS`. The host offset arrives in
  Task 8.
- The `Display` impl is a civil-from-days conversion (Howard Hinnant's algorithm), with no new
  dependency.

**Files:**

**Interfaces:**
```rust
// kernel/clock.rs
pub(crate) struct WallHold { held: Option<WallTime> }
impl WallHold {
    pub(crate) fn new() -> WallHold;
    /// max(reading, held); Err(stop) when reading < held - CLOCK_TOLERANCE.
    pub(crate) fn read(&mut self, clock: &dyn Clock) -> io::Result<WallTime>;
    /// Raises `held` to `floor` (never lowers it).
    pub(crate) fn seed(&mut self, floor: WallTime);
}
/// The latest wall time this store provably saw, recovered without a log-format change:
/// max over ApiKey.created_at and CronRow (next_due - interval_nanos), read BEFORE
/// CronScheduler::upsert rewrites interval_nanos. None for a store with neither.
pub(crate) fn recorded_wall_floor(snap: &Snapshot) -> io::Result<Option<WallTime>>;
```
- At writable start (open as single node or primary, and promote), before `cron.upsert`:
  - compute the floor;
  - if `wall < floor - CLOCK_TOLERANCE`, return the refusal;
  - otherwise `hold.seed(floor)`.
- Errors use the kernel's existing `Refusal` type (`mod.rs:322`), so a stopped kernel ends the
  process, as for every other named stop.

**Copy (binding).** `{d}` is the gap as `Duration`'s `Debug` (for example `3600s`). Times use
`WallTime`'s `Display`. `{verb}` is `open` or `promote`.
- Stop: `clock went backwards: this node's wall clock reads {wall}, {d} behind {held}, the latest time it already used — more than the 60s charpente tolerates (CLOCK_TOLERANCE). The node stopped rather than extend sessions or delay schedules by that much.
