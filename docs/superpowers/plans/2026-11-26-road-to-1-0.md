# The road to 1.0: document pass — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make MANIFESTO, DECISIONS, PLAN, README, CLAUDE.md, CHANGELOG and LEDGER say what
charpente now intends for 1.0, as the approved spec decides, in one coherent docs-only pass.

**Architecture:** DECISIONS goes first, because its new §16 is what every other edit points
to. Then come the two census-scanned docs (MANIFESTO, README), PLAN's 1.0 milestone,
CLAUDE.md, and the ledger record. Each task is one document and its gate. No code changes,
except one test constant in `crates/guide-examples/tests/claims_census.rs`.

**Tech Stack:** Markdown. The doc gates are Rust tests in `crates/guide-examples` and
`crates/charpente-cli/tests/demo.rs`.

**Spec:** `docs/superpowers/specs/2026-11-26-road-to-1-0-design.md` (approved 2026-11-26,
commit `b2c48266`). Read it whole before Task 1. §7 fixes what each decision says, and §8
fixes what each document gets. This plan fixes where each edit lands and how it is checked.

## Global Constraints

- The 1.0 goal, verbatim wherever it is quoted in full: "An outside team can hand one consequential workflow to agents, let them change it many times, and accept each change without reading the code. charpente gives them a verdict anyone can re-check, saying which of the team's promises were checked, how strongly, and what nothing checked. Their data and unfinished work survive every charpente upgrade." The one-line form: "accept an agent's change without reading it, and keep the business you already have."
- The data promise starts at 1.0.0. Data written by any 0.x release or release candidate does not reach 1.0.0. Downgrades stay unsupported.
- 1.0 is gated on the predictions registered before the full experiment. One rerun is allowed, and §2 reopens on a second miss.
- No versioning text. Nothing says how API breaks are numbered after 1.0. §15's "the minor version bumps" stands through 0.x.
- APIs still change in place, with no parallel APIs. Only stored data and unfinished work are carried, from 1.0.0.
- Unchanged: DECISIONS §6, §7, §10, §14, every hard rule, one log, one commit point, no sharding, no SQL-first interface, no porting existing apps, no hosted control plane on the roadmap, and the twin parked.
- The census: in README.md and MANIFESTO.md, every digit outside backticks, URLs, `dddd-dd-dd` dates, `20dd` years, `§N`, `MN` and "hard rule N" is a figure, and so are the words in `WORD_FIGURES` (for example "sixteen", "thousands of"). The only new figure allowed is "1.0", written exactly so; never "1.0.0" in those two files. No stage numbers, "F1"/"F2", dollar amounts or counts.
- MANIFESTO keeps the exempt strings "thousands of seeded universes per night" (§6) and "thousands of times" (§9) verbatim. A stale exemption is a test failure.
- README's quoted runs and `## Example: a double charge` / `## Install` sections are pinned by `crates/charpente-cli/tests/demo.rs`. Don't edit inside them.
- CLAUDE.md's workspace map and test lists are held by `doc_inventory.rs`. Each test list stays on one line. Don't touch them.
- docs/BENCH.md is the only source of performance numbers. Quote none.
- No employer named or alluded to. No Co-Authored-By trailers. Commit named paths only (`git commit -- <paths>`), with messages in the repo's `area: what changed` style.
- Prose follows the 2026-11-21 root-doc voice: plain, direct, no "not X but Y" constructions, no bold-label sprawl. Each prose task runs the `humanizer:humanizer` skill over its changed paragraphs before the commit, and applies fixes that keep the meaning.
- zsh: use `set -o pipefail`, or `${pipestatus[1]}` (lowercase, 1-indexed), to read cargo's status through a pipe. Pipe through `tee`, never `tail`. Count `^test result: ok` lines; never infer green from a missing `FAILED`.
- Scratch logs: start every command block that writes a log with `S=/private/tmp/claude-501/-Users-noahmitchem-Documents-GitHub-charpente/13da46e3-481e-477f-b9d9-658f8e3f1e2c/scratchpad`. Shell state does not carry between calls.
- grep on this machine: use `-E` for alternation and `-w` for whole words. BRE `\|` and `\b` can match nothing without saying so.

1. **README reads as shipped.** Someone reading "Where it's going" or the new Limits line takes an unbuilt stage for a shipped feature. Every sentence must be future tense or say it isn't built. Task 4, Step 5 checks this.
2. **The documents disagree on the data promise.** If DECISIONS §15/§16, MANIFESTO §8, PLAN's exit criterion 4, README's Limits and CLAUDE.md say different things about when it starts or whether 0.x data crosses, an adopter reads the wrong one. Task 6, Step 2 reads every mention side by side.

5. **Versioning or status text sneaks in.** A sentence about major/minor numbering after 1.0, or task-level status in CLAUDE.md's "Current state", contradicts a decision. Tasks 2, Step 6 and 5, Step 4 check this.
