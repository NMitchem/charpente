# 0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.4.0. A blind agent's checks become as hard to get wrong as its app:
- a second kernel on a spent App does not compile;
- a check that tested nothing fails;
- the recovery code every app pastes is a library helper;
- the shrinker deletes whole items;
- a mutation run fits a session;
- events read as the app's own types;
- the API sits on one compiled page.

**Architecture:**
- **The helper.** It lives in a new `charpente_sim::drive` module. That gives `charpente-sim`
  a normal dependency on `charpente`. `charpente`'s dev-dependency on `charpente-sim` becomes
  path-only, the precedent `charpente-macros` already sets (`crates/charpente-macros/Cargo.toml`,
  "Cyclic dev-dependency").
- **Per-request answers.** `SimSource` records each pushed request's answer in its own slot,
  so nothing is ever matched by position.
- **The quick mutation pass.** The harness learns it from two environment variables read
  where `CHARPENTE_SIM_NO_SHRINK` is (`crates/charpente-sim/src/lib.rs:3255`). The verb runs
  cargo-mutants twice: once quick, then at full strength for what the first pass missed.
- **The shrinker.** It deletes every chunk length from 8 down to 1.

**Tech Stack:** Rust 1.99 (pinned), the workspace crates, trybuild (in `charpente-macros`),
cargo-mutants 27.1.0, the `toml` crate (new, in `charpente-cli` only), the edge harness, and
the launch-run tools (`docs/experiments/2026-10-launch-run/tools/`).

**Spec:** `docs/superpowers/specs/2026-10-28-0.4.0-design.md` (437f1e76). Executors read it,
and CLAUDE.md, before their task. Part letters (A–G) and §1 item numbers below are the spec's.

## Global Constraints

- **Hard rule 1.** Nothing in `charpente-sim`'s harness or `drive` reads a clock; the shrink
  budget stays a replay count. Environment reads live beside the existing
  `CHARPENTE_SIM_NO_SHRINK` read.
- **Determinism.** Only the named steps in Task 0's table may move a recorded batch or a
  pinned seed:
  - **N1:** merge-fixture's pins (Task 1);
  - **N2:** batches holding an untested check, and platform suites in which every universe
    gave up (Task 6);
  - **N3:** the examples' and the scaffold's recorded output (Task 10);
  - **N4:** shrunk inputs and replay counts (Task 11).

  Every other task runs `$SDD/oracle3.sh <label>` and must see exit 0. Batches stay
  byte-identical across `--jobs`.
- **Exit codes:** 0 green; 1 any failed run, unmet `require`, or untested check in a batch;
  2 usage, build, infrastructure, or no check matched. A `--seed` replay of a skipped run
  exits 0, and a quick pass (`CHARPENTE_SIM_FIRST_RUNS`, Task 12) judges failed runs only
  (amended in execution, 2026-10-31).
- **Copy is binding.** Every product-surface string this plan gives is exact and pinned by a
  test (hard rule 5). Where the plan gives no string, the implementer writes one in the
  spec's shape and pins it.
- **Hard rule 6.** The docs a task's code changes land in that same task: GUIDE, DESIGN,
  examples, and CHANGELOG's `## 0.4.0 (unreleased)` section, under `### Changed` or
  `### Removed` for breaks.
- **New dependency edges:**
  - `charpente-sim → charpente` (Task 7). Reason: the helper drives a `Kernel` over an
    `App`.
  - `charpente-cli → toml` (Task 2). Reason: it reads manifests as written, which
    `cargo metadata` does not show.

  No other new edge, and nothing new inside the deterministic boundary that does IO,
  threading or time.
- **New workspace test files** are added to CLAUDE.md's test lists in the same commit:
  `charpente-sim`'s `drive` and `events`, and `guide-examples`' `driver_census` and
  `api_census`. `guide-examples`' `doc_inventory` gate enforces this.
- **Commits:** on `main`, named paths only, no trailers (CLAUDE.md). Immediately before each
  commit, run `git log --oneline -1` and `git status --short`. Stop and report if HEAD
  moved or unrelated files are dirty: another session may share this tree.
- **Verification (implementers):**
  - Run per-package suites only:
    `cargo test -p <pkg> --no-fail-fast 2>&1 | tee $SDD/logs/<task>-<pkg>.log`.
  - Take the exit code from `${pipestatus[1]}` (zsh), and count
    `grep -c '^test result: ok'`.
  - Never run `cargo test --workspace`; the controller runs it in
    `~/Documents/GitHub/charpente-gate`.
  - Bound long runs with `perl -e 'alarm N; exec @ARGV' --`.
  - Run everything in the foreground.
  - Before every commit, run `cargo fmt --all --check` and
    `cargo clippy --workspace --all-targets -- -D warnings`.
- **Network:** cargo's own fetches and `docker pull` only. No email address in any request.

## Review Focus

1. **An event log longer than one scan page.** A's driver read `scan_from(0, 4096)` and
   would silently truncate. The typed reads must page to the end. Test in Task 8.
2. **A faulted-phase 500 whose body is not fault fallout** (a handler's own error). It is
   the app's answer: never re-sent, never counted as unanswered. Test in Task 9.
3. **`--runs 1` or `--runs 4` while iterating, with the one run skipped.** The batch now
   exits 1, and the fix line must say to raise `--runs` among the fixes, as the unmet-require
   message C praised does. Test in Task 6.
4. **A relative path dependency that stays inside the copied tree** (a workspace sibling).
   It must not be refused. Only a path that leaves the tree is. Test in Task 2.
5. **An app that declares outbound hosts while the workload registered no remote.** The
   helper's error must say what to call (`sim.remote(…)`), never panic. Test in Task 9.

### Task 9: The recovery helper, `charpente_sim::drive` (C)

**Files:** `crates/charpente-sim/src/drive.rs` (new), `crates/charpente-sim/src/lib.rs`
(`pub mod drive;`), `crates/charpente-sim/tests/drive.rs` (new), `CLAUDE.md` (test list)

**Interfaces:**
- Consumes:
  - `boot_through_fallout`, `wait_out_clock_refusal`, `is_fault_fallout` and
    `clock_fallout` (`checks.rs`);
  - `Sim::{restart, quiesce_disk_faults, quiesce_clock_faults, quiesce_outbound_faults,
    outbound, gave_up, give_up, clock, now}`;
  - `SimSource::{new, push_at, answers}` (Task 7);
  - `Kernel::{new, with_outbound, run, app}`;
  - `App::outbound_hosts`.
- Produces:
  ```rust
  pub struct Drive<'s> { /* sim, build */ }
  impl<'s> Drive<'s> {
      pub fn new(sim: &'s Sim, build: impl Fn(&Sim) -> std::io::Result<App> + 's) -> Drive<'s>;
      /// Steps 1 and 2. Requests are offsets from the phase's start.
      pub fn faulted_phase(&self, requests: &[(Duration, Request)], horizon: Duration) -> Result<Phase, String>;
      /// Steps 3 and 4: power-cycle, quiesce, boot, re-send what went unanswered, run to `now + tail`.
      /// `Ok(None)`: the run gave up on a durable refusal.
      pub fn recover(&self, phase: &Phase, tail: Duration) -> Result<Option<Recovered>, String>;
  }
  pub struct Phase { pub requests: Vec<Request>, pub answers: Vec<Option<(u16, Vec<u8>)>> }
  impl Phase { pub fn status(&self, i: usize) -> Option<u16>; }
  pub struct Recovered { pub kernel: Kernel, pub resent: Vec<Option<(u16, Vec<u8>)>> }
  impl Recovered { pub fn status(&self, i: usize) -> Option<u16>; }
  ```
  - `resent[i]` is `Some` only for a request that was re-sent.
  - Fault fallout is `is_fault_fallout(t) || clock_fallout(sim, t)` everywhere.

  **The behaviour, one rule per step** (spec C):
  - **Boot.** A first boot that never gets past fallout gives an empty phase: every
    `answers[i]` is `None`, and no give-up.
  - **Faulted phase.** Fallout ends it and is never a give-up or a skip. A non-fallout
    error is `Err` with the kernel's text.
  - **Tail.**
    - It calls `sim.restart()`, then quiesces disk and clock always, and outbound when
      the freshly built app's `outbound_hosts()` is non-empty. Read the hosts before
      `Kernel::new`, because building a kernel takes them out of the App.
    - The tail's boot goes through `wait_out_clock_refusal`. This helper is the only
      caller in shipped code (Task 10's census).
    - It builds the kernel with `with_outbound` exactly when there are hosts.
    - A durable refusal gives `Ok(None)`. Any other failure to boot is
      `Err("the fault-free tail could not boot")`.
    - A kernel stop in the tail is `Err(format!("the fault-free tail's kernel stopped: {e}"))`.
  - **Re-send.** A request is re-sent when its answer is `None`, or when it is `Some` with
    a 5xx body that is fault fallout. A 4xx, or a non-fallout 5xx, is the app's answer
    (Review Focus 2).
  - **Missing remote.** When the app declares hosts and `sim.outbound` fails because no
    remote is registered, the error names the fix:
    `the app calls <host>, but the workload registered no model for it — call sim.remote("<host>", …) before Drive::faulted_phase`
    (Review Focus 5).

  - `a_first_boot_lost_to_fallout_still_reaches_the_tail_and_resends_everything`;
